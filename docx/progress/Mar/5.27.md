## 十、正式大表口径调整

严格来说，`ResUNet residual` 不是复现某篇论文的方法，只能作为工程 sanity baseline 或 internal baseline。

正式论文大表应该主要由三类方法组成：

```text
1. Traditional interpolation
   Linear / Cubic

2. Published strong baselines
   EDSR2D / EDSR3D / RDN / RCAN / SwinIR / HAT / ArSSR / SAINT / CycleINR / I3Net

3. Ours
   后续真正提出的方法
```

以后表格必须补充这些字段：

| Dataset | Modality | Scale | Direction | Method | PSNR mean | SSIM mean | MAE mean | MSE mean | NCC mean |
|---|---|---|---|---|---:|---:|---:|---:|---:|
| IXI | T1 | x4 | z / through-plane | Linear | 24.6442 | 0.7756 | 64.5210 | 21690.3990 | 0.9075 |
| IXI | T1 | x4 | z / through-plane | ResUNet residual | 28.8887 | 0.8808 | 37.8351 | 8148.3277 | 0.9621 |

注意：

```text
Scale 必须写清楚，例如 x2 / x3 / x4。
Direction 必须写清楚，例如 axial z-direction / through-plane。
Dataset 必须分开报，不能把 IXI、TopCaw、fastMRI 混成一个平均值。
```

当前我们的 IXI 实验是：

```text
stride = 4
保留 z=0,4,8,... 原始切片
预测 z=1,2,3,5,6,7,...
因此属于 through-plane x4 slice interpolation / super-resolution。
```

## 十一、截图中 baseline 的定位

截图中的方法可以分成几组：

| Method | 原始方向 | 是否适合我们大表 | 优先级 | 说明 |
|---|---|---|---|---|
| EDSR2D | 2D single image SR | 可以 | 高 | 经典 CNN SR，可作为自然图像 SR 迁移到医学层间插值的 baseline |
| EDSR3D | 3D SR 改造版 | 可以 | 中 | 更吃显存，可作为 3D CNN baseline |
| RDN | 2D image SR | 可以 | 高 | 残差稠密网络，常作为强 CNN SR baseline |
| RCAN | 2D image SR | 可以 | 高 | channel attention SR baseline，适合和 ResUNet 区分 |
| SwinIR | Transformer image restoration / SR | 可以 | 高 | Transformer SR 强 baseline |
| HAT | Hybrid Attention Transformer SR | 可以 | 中高 | 很强但较重，适合作为高性能 SR baseline |
| ArSSR | 3D MRI arbitrary-scale SR | 非常适合 | 很高 | 医学 MRI 3D 任意倍率 SR，和 IXI 最贴近 |
| AdaCoF | video frame interpolation | 可作为跨领域对照 | 中低 | 医学切片没有真实运动场，适合说明视频插值方法不一定适合 MRI |
| RSTT | video restoration / VFI / VSR | 可作为跨领域对照 | 中低 | 较复杂，优先级低于医学 SR 方法 |
| IFRNet | efficient video frame interpolation | 可作为跨领域对照 | 中 | 轻量，若要选视频插值 baseline，可以优先它 |
| TVSRN | transformer volumetric SR | 适合 | 高 | 医学体数据 SR，适合与 ArSSR / SAINT / CycleINR 同组 |
| SAINT | medical slice synthesis | 非常适合 | 很高 | CVPR 2020，专门做 medical slice synthesis，必须重点考虑 |
| I3Net | medical slice synthesis | 非常适合 | 暂缓 | 同学正在用 IXI 复现，先不重复投入 |

下一阶段更合理的公开 baseline 顺序：

```text
Priority 1:
  SAINT
  ArSSR
  CycleINR

Priority 2:
  EDSR2D
  RDN
  RCAN
  SwinIR

Priority 3:
  HAT
  EDSR3D
  TVSRN

Priority 4:
  IFRNet / AdaCoF / RSTT
```

理由：

```text
SAINT / ArSSR / CycleINR 是医学体数据或医学切片合成方向；
EDSR / RDN / RCAN / SwinIR 是强通用 SR baseline；
IFRNet / AdaCoF / RSTT 是视频插值方法，可以证明跨领域方法迁移到医学切片并不一定最优。
```

## 十二、fastMRI 下载规划

fastMRI 和 IXI 不完全一样：

```text
IXI:
  已经是重建后的 3D NIfTI 图像，最适合先做 through-plane interpolation。

fastMRI:
  主要是 raw k-space / HDF5 / DICOM 数据，原始目标是 accelerated MRI reconstruction。
  它更权威，但预处理成本更高。
```

目前不建议一上来下载 brain multicoil train 全量数据，因为 brain multicoil train 接近 TB 级，且处理 k-space/multicoil 会先把工程复杂度拉满。

如果目标是延续当前 IXI 的 image-domain through-plane interpolation，优先下载：

| Step | 下载内容 | 大小 | 用途 |
|---|---|---:|---|
| 1 | brain_fastMRI_DICOM | 38.8 GB | 最贴近当前 IXI 脑 MRI 插值任务，先做 DICOM 体数据读取、病例整理和 x2/x4 伪降采样 |
| 2 | knee_singlecoil_val | 14.9 GB | 熟悉 fastMRI HDF5 / k-space 数据结构，做工程验证 |
| 3 | knee_singlecoil_train | 72.7 GB | 如果 HDF5 流程跑通，再做正式训练 |

如果目标是走 fastMRI 官方 k-space reconstruction / HDF5 路线，推荐下载顺序：

| Step | 下载内容 | 大小 | 用途 |
|---|---|---:|---|
| 1 | knee_singlecoil_val | 14.9 GB | 先写 loader、检查 HDF5 结构、做小规模可视化和数据审计 |
| 2 | knee_singlecoil_test | 1.4 GB | 补充测试流程，但注意 test 可能不适合作为有 GT 的正式评估 |
| 3 | knee_singlecoil_train | 72.7 GB | 若 val 跑通，再做正式训练 |
| 4 | brain_multicoil_val_batch_0 | 93.5 GB | 后续如果要转 brain k-space / multicoil，再从一个 val batch 开始 |
| 5 | brain_multicoil_train batch | 每个约 90-100 GB | 暂时不建议立刻下载全量 |

因此当前最推荐分两种：

```text
做图像域脑 MRI 插值：
  先下载 brain_fastMRI_DICOM

做 fastMRI k-space / HDF5 工程验证：
  先下载 knee_singlecoil_val
  再下载 knee_singlecoil_train
```

如果磁盘压力大：

```text
只下载 brain_fastMRI_DICOM 或 knee_singlecoil_val 其中一个。

当前课题更推荐 brain_fastMRI_DICOM；
如果后续要做 k-space reconstruction，再补 knee_singlecoil_val。
```

暂时不推荐：

```text
brain_multicoil_train 全量；
prostate / breast 全量；
DICOM 全量。
```

fastMRI 下载命令建议继续使用官方给的：

```powershell
curl -C - "<signed url>" --output <file>.tar.xz
```

不要把 signed URL 放进论文、GitHub 或公开文档；这些链接有时效性，也带访问签名。
