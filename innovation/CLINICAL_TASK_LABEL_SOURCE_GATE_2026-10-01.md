# Clinical-task label source gate for the released-plane MIRA audit

**Status: source gate failed for MSValid; no clinical endpoint has been run.** The [MSValid official ZIP central-directory inventory](literature/msvalid_remote_inventory.json) (SHA-256 `b12dfbdb3a298d5011b2d3ec62e3b69206747f86d26c01106c7e3215552492f7`) was obtained with [metadata-only HTTP ranges](literature/msvalid_remote_inventory.py), transferring 96,549 bytes rather than the 2,909,364,362-byte archive. It lists 687 files including macOS companion entries; after excluding `__MACOSX/`, there are 398 `.nii.gz` volumes and six `.DS_Store` files. All 398 image basenames end in `_T1.nii.gz`, `_T2.nii.gz`, or `_FLAIR.nii.gz`. No member has a segmentation, lesion, mask, annotation or label name, and no non-image label file is listed. This inventory proves only that **this official ZIP does not itself supply a directly pairable label file**. It does not rule out separately released annotations; it also does not inspect image pixels or prove that a label is in the T2 target plane.

The currently used [MSValid cohort](MSVALID_IXI_WEIGHTS_SECONDARY_RESULT_2026-10-01.md) is 84 patients/479 targets, [ReMIND](REMIND_NATIVE_T2_CONFIRMATION_RESULT_2026-10-01.md) 62/248, and [processed UPENN](UPENN_GBM_PROCESSED_T2_CONTEXT_RESULT_2026-10-01.md) 374/1,496. All three have intensity targets, but none has a verified pathology label linked to **the exact target plane and source series** in the frozen MIRA analysis. UPENN's selected 374 series are all derived/secondary; finding a GBM label from another release would require a separate transform/provenance audit before use. Anatomical volumes from an automatic segmenter could be a pipeline-sensitivity analysis, not independent clinical ground truth.

The [UPENN official-source check](UPENN_GBM_LABEL_ALIGNMENT_GATE_RESULT_2026-10-01.md) has since found expert-corrected tumor labels aligned to atlas-registered NIfTI volumes, with an explicit submitting-group warning that these do not align to DICOM by design. Those labels cannot simply be overlaid on the frozen 374 DICOM series. A separate [metadata-only NIfTI feasibility check](UPENN_GBM_NIFTI_LABEL_FEASIBILITY_RESULT_2026-10-01.md) found 232 baseline scan rows with corrected labels available and 114 subject prefixes overlapping the DICOM selection, but no same-scan/space alignment to frozen DICOM targets. The source gate remains failed for all three frozen endpoints; the atlas NIfTI route requires its own protocol.

Before any task-metric run, freeze and archive all of the following:

1. The official label release, license/citation and file hashes; patient and series UID mapping; annotator/label definition and which scans were viewed during annotation. Document any source overlap with model development.
2. A no-resampling or fully documented physical-space transform from each label to the actual withheld T2 target plane. Check orientation, spacing, center coordinates, voxel shape and field of view per series; audit nonmatching cases and stop if registration obscures the target-plane identity. Never treat an axial label on a different visit or derived series as native truth by filename alone.
3. A patient-level inclusion list and label-positive/negative target counts **before** evaluating the model outputs. Keep every failed mapping and poor-quality case visible. Ensure the same target, ROI, normalization and phase-specific observation budget in both conditions.
4. One primary task endpoint matched to the available annotation, for example lesion-box sensitivity at a preselected false-positive burden, or Dice/volume error for a validated mask. Compare shared and disjoint predictions against the **same fixed label and reference** using patient-paired estimates and a patient bootstrap CI; report prevalence and all failure strata. Also report global and lesion-region MSE so an apparent task gain cannot be presented as overall reconstruction gain.
5. A negative decision rule: if no same-plane authoritative label exists, stop at the descriptive intensity audit. If labels map but the patient-paired clinical endpoint is null or adverse, report that result and do not claim clinical benefit from `Delta O`. If the endpoint is positive only after choosing a favorable threshold, model or subgroup, classify it as exploratory and require another cohort.

This is a preparation protocol, not a pre-registration of a chosen annotated cohort. It reserves no GPU budget and does not authorize reading the locked IXI test set. A valid matched original-acquisition source remains a **separate** requirement for causal language about measurement identity; task labels alone would not satisfy it. The [forward-citation audit](literature/2026-10-01_four_seed_forward_citation_result.md) makes this distinction material: recent MRI studies already assess pathology recall or segmentation consequences, whereas the current MIRA result is a retrospective paired-error measurement.
