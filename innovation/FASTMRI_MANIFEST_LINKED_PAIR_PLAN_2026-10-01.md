# Frozen manifest-linked UID pair screen

Frozen before pair calculations on 2026-10-01, after the [crosswalk](FASTMRI_MANIFEST_UID_CROSSWALK_PLAN_2026-10-01.md) showed that literal DICOM `T2` labels cover only part of the manifest selection. Use exactly the same SHA-256-fixed manifest, 61 case rule, 138 `is_t2=True` rows, and validated `first_dicom` pointers. Within each case, deduplicate the referenced `SeriesInstanceUID` values and compare **every unordered pair** of distinct referenced UIDs, regardless of DICOM series-description text. This is a manifest-classified candidate screen, not proof that every linked UID is a clinically valid T2-weighted acquisition. Retain whether zero, one or both pair members have a literal `T2` DICOM label.

Read all `.dcm` files in each selected case with `pydicom.dcmread(..., stop_before_pixels=True)`, group by UID and require each referenced UID to exist in its case directory. Reuse the frozen 16-plane, position, `ORIGINAL/PRIMARY` 2D, SOP-distinctness, frame, matrix, orientation, spacing, thickness, TE, TR and time checks in the prior [header gate](FASTMRI_ALL_T2_HEADER_GATE_PLAN_2026-10-01.md). A missing literal DICOM T2 label does **not** fail the geometry/protocol check in this manifest-linked screen; it is a separate classification uncertainty. Report center match, technical match, usable distinct time and full header trace-back candidate separately. Even a full header candidate does not prove independently acquired raw planes.

Output only anonymous case and series ordinals, counts, scalar differences and technical/timing failure codes. No source IDs, paths, raw UIDs, source descriptions, dates or pixels. Refuse changed selection, missing series or existing output. This screen cannot authorize pixels, source publication or a pure acquisition-identity claim without independent source records and a separately frozen pixel-stage protocol.
