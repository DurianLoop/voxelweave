# MSD Task01 first-pair NIfTI header gate

Frozen after the official registry/S3 tar-header inventory and before any NIfTI byte-range request. The source is the exact 7,608,266,240-byte `Task01_BrainTumour.tar` object indexed in [the official inventory](MSD_TASK01_OFFICIAL_SOURCE_INVENTORY_RESULT_2026-10-01.md). Use the lexicographically first exact training pair from `dataset.json`, `BRATS_001`, with `imagesTr/BRATS_001.nii.gz` and `labelsTr/BRATS_001.nii.gz`. This is a metadata-only pilot, not patient selection for the later scientific endpoint.

Request at most the first 4,096 compressed bytes of **each** exact tar member by the recorded HTTP Range offsets. Require HTTP 206, matching `Content-Range`, unchanged S3 object size/ETag, and exact returned length. Use a gzip decompressor with a maximum output of 352 bytes; do not inflate image voxels. Parse with `nibabel.Nifti1Header` from the header bytes and record magic, datatype, dimensions, pixdim, qform/sform codes and best affine; archive only these metadata and source/prefix hashes, never the compressed bytes. The image must be a 4D NIfTI with exactly four modalities, the label a 3D NIfTI, identical first three dimensions and best affine within absolute tolerance `1e-4`, and finite positive spatial spacings. If the first 4,096 compressed bytes cannot yield a complete header, one bounded retry may use 8,192 bytes and must be recorded. If any requirement fails, stop before voxel download and revise source eligibility on evidence, not on model outcome.

Even if this gate passes, it confirms only **same release-grid pairing** for one preselected case. It does not validate all 484 pairs, mask contents, actual acquisition provenance or model performance. A separate pre-pixel experiment protocol must freeze patient/target selection, clinical ROI and controls before requesting full NIfTI members. No GPU, training process or locked IXI test file is involved.
