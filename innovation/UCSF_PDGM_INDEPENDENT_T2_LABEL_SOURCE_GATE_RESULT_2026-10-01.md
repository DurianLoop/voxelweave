# UCSF-PDGM T2/label source gate: metadata result

This is the read-only follow-up to the [frozen gate](UCSF_PDGM_INDEPENDENT_T2_LABEL_SOURCE_GATE_PLAN_2026-10-01.md). The [TCIA collection snapshot](literature/source_cache/ucsf_pdgm_official_2026-10-01/index.json), [PMC data descriptor and v5 CSV index](literature/source_cache/ucsf_pdgm_descriptor_2026-10-01/index.json), and their archived raw files are the evidence. No UCSF image or label bytes were downloaded or decoded; no GPU or locked IXI test was used.

## Source and overlap

The current TCIA release is UCSF-PDGM version 5 (2025-05-30), DOI [10.7937/tcia.bdgf-8v37](https://doi.org/10.7937/tcia.bdgf-8v37), CC BY 4.0. Its image/annotation package is listed as 142 GB of NIfTI/BVEC through IBM Aspera Connect. The source page explicitly corrects the original paper's **501 patients** to **495 people and 501 examinations**: six records are follow-up scans of another listed ID, renamed with `_FU...` suffixes. The v5 CSV has 501 unique examination IDs, six follow-up rows and 495 baseline rows. Any evaluation must group by person and exclude or explicitly account for follow-up scans, particularly the 175-day follow-up.

The v5 CSV has 298 nonempty `BraTS21 ID` mappings: 262 BraTS21 segmentation Training and 36 Validation. On baseline rows alone, 293 are mapped (257 Training, 36 Validation) and 202 lack a mapping. TCIA's version-2 note says this mapping was added **to prevent data leaks** when using BraTS 2021. The descriptor says a portion of UCSF-PDGM appeared in BraTS 2021 and 387/501 exams were independently reviewed for that challenge. Its references 6-9 denote earlier *studies*, not proof of additional public image identity. Neither a blank BraTS21 ID nor a different release name proves disjointness from MSD Task01, other BraTS versions, or prior model training. No direct patient-level crosswalk to the anonymized MSD `BRATS_...` IDs has been established.

## Imaging and labels

The descriptor reports a 3-T standardized protocol including 3D T2-weighted MRI. Published image sequences were nonlinearly registered/resampled into the 1-mm T2-FLAIR space and skull stripped; the collection page says original DICOM is unavailable. Thus this is a **processed-release-grid** candidate, not a source for the project's native independent 2D-slice acquisition claim. The v5 version note refers to original-orientation `DTI_eddy_noreg` files; that exception must not be generalized to the T2 or tumor-mask files.

Tumor compartment masks were initiated by a BraTS ensemble, manually corrected and reviewed by expert neuroradiologists. TCIA notes a version-2 rounding fix to `*tumor_segmentation.nii.gz`. A subsequent [read-only package file-list pilot](UCSF_PDGM_SINGLE_CASE_FILE_LIST_RESULT_2026-10-01.md) found 501 v5 examination directories matching the 501 CSV IDs after numeric padding normalization. The preselected `UCSF-PDGM-005` directory lists exact-case T2 (2,693,713 declared bytes) and tumor-mask (50,345 bytes) symbolic links. This establishes file-name pairing for **one** case, but not link target accessibility, the all-case label denominator, or identical voxel shape and affine. A label cannot yet be overlaid on a T2 array. The `BraTS21 Segmentation Cohort` field identifies challenge participation; it is not a verified inventory of label files in the TCIA v5 package.

## Access result and next gate

The archived TCIA page links the 142-GB package and instructs IBM Aspera Connect. The official public file browser supplied the above directory listing, but the collected source material still has no documented direct two-file download workflow. The earlier [UPENN Faspex two-file attempt](UPENN_ASPERA_TWO_FILE_ACCESS_RESULT_2026-10-01.md) used a different public package and ended at token authentication with zero bytes; that result cannot establish access to UCSF. An attempted read of IBM's Connect documentation endpoint in this environment failed at connection setup, so no vendor-supported transfer-spec invocation was verified here. No UCSF Aspera transfer was attempted.

**Later access update:** IBM's [documented ascli route](UCSF_PDGM_ASCLI_TWO_FILE_ACCESS_RESULT_2026-10-01.md) was tested after this metadata gate. Public-link CLI browse and exact-two-file transfer-spec requests succeeded, but both bounded CLI transfer variants received Faspex HTTP 500 and wrote zero file bytes. Thus the preceding paragraph describes the initial gate, not the latest access state. The two NIfTI headers remain unread.

For a later bounded pilot, use the now frozen `UCSF-PDGM-005` T2 and tumor-segmentation paths under the [two-file header protocol](UCSF_PDGM_TWO_FILE_HEADER_PROTOCOL_2026-10-01.md), after obtaining a documented Connect workflow. Unmapped is only a provisional filter: check any released BraTS/MSD identity crosswalk and model-development history before calling it independent. Read NIfTI headers first; require matching shape, orientation and affine under the frozen tolerance. Label-value and identity checks are separate gates before any tumor metric. Freeze target-slice rule, tumor and local-negative ROIs, patient-level denominator, raw/pipeline linear and PCHIP comparators, and all failure accounting **before** reading pixels. If the access or same-grid gate fails, do not run tumor metrics or combine the UCSF mask with UPENN/MSD images.

**Decision:** UCSF-PDGM is a plausible second processed T2 pathology source with an exact-case T2/mask file-name pair, but it has **not passed** independent-patient or file-level alignment gates. The existing IXI-to-MSD tumor deficit remains a single annotated-release observation, not external pathology confirmation or a publishable method claim.
