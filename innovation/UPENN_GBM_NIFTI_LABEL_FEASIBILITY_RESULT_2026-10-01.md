# UPENN-GBM aligned NIfTI label route: metadata-only feasibility

The [official TCIA collection page](literature/source_cache/upenn_gbm_collection_page_2026-10-01.html) offers a separate approximately 69 GB NIfTI/segmentation package and states that expert-corrected tumor labels align with its SRI-atlas-registered NIfTI images, **not with DICOM by design**. After the [DICOM alignment gate](UPENN_GBM_LABEL_ALIGNMENT_GATE_RESULT_2026-10-01.md), this route is a potential **new study in a different release space**, not a way to attach labels to the frozen 374-patient DICOM result. No NIfTI or patient pixels were obtained here.

Two small TCIA CSVs were retrieved directly from the URLs linked on that official page. Their exact bytes, URLs, SHA-256 values and the reproducing [metadata script](literature/audit_upenn_gbm_label_availability.py) are in the [source index](literature/source_cache/upenn_gbm_label_availability_2026-10-01/index.json). Structured CSV parsing and an exact scan-ID-set check gave:

| Metadata-only count | Result |
|---|---:|
| Data-availability scan rows / distinct subject prefixes | 671 / 630 |
| Acquisition-parameter scan rows / exact ID-set match | 671 / yes |
| Rows marked corrected tumor segmentation available | 232 |
| Suffix of all corrected-label scan IDs | _11 (232/232) |
| Frozen selected DICOM subject prefixes found in availability table | 374/374 |
| Selected DICOM subject prefixes also having a corrected-label row | 114/374 |

The 114 is only a **string-prefix intersection** between selected DICOM PatientIDs and baseline availability IDs. It is not a scan-level match, transformation, same target plane, or label-positive-case count. The 232 available corrected-label rows have distinct subject prefixes, but their actual NIfTI file presence, masks, grid and lesion content have not been inspected. The collection page's public package uses an IBM Aspera access link; a metadata-only HEAD request returned a small HTML page, not a file inventory. This audit did not download or stage the 69 GB package.

**Bounded access check:** direct GET of that public link returned the IBM Aspera 5.0.15 web-app HTML (not a file list), whose configuration names an API v5 base. A guessed read-only public-package API path returned HTTP 404; that does not prove the package is unavailable or that partial official transfer is impossible. No Aspera client executable was found in this workspace, and no package token, credentials or large transfer were used. File-level eligibility must wait for a supported official listing/download route.
The current public web-app script exposes a package-file listing call under API v5; a read-only request for the linked package's root listing without a session returned HTTP 401, "Add an HTTP authorization header to your request." This shows the direct API is authorization-gated in this environment. It does not prove an authorized public-link browser/client session cannot list or select files. No authentication bypass or bulk transfer was attempted.

**Later official public-link update (2026-10-01):** the webpage's own `authorize_public_link` flow did grant a temporary public session and yielded the [file-level package inventory](UPENN_NIFTI_OFFICIAL_PACKAGE_INVENTORY_RESULT_2026-10-01.md). The earlier unauthenticated 401 is therefore superseded as an access blocker for *listing*. The package shows 147 candidate corrected-segmentation links among 232 CSV-marked scans, with 60 approximately 0.9 mm T2 metadata candidates. Neither file transfer nor same-grid header validation has occurred; the approved public configuration has no HTTP gateway, and local Aspera Connect was absent.

**Acquisition-metadata and nonpixel follow-up.** Among 232 corrected-label baseline scan rows, official T2 Slice Thickness fields are 3 mm in 135, approximately 0.9 mm in 86, 5 mm in eight, 4 mm in two and 1 mm in one. Among the 114 subject-prefix overlaps with the frozen DICOM selection, 112 are 3 mm and two are 4 mm; the approximately 0.9 mm group is outside that selected DICOM stratum. The frozen NBIA series list contains 83 exact-description 192-image T2 SAG SPACE: Processed_CaPTk series among those 86 thin-metadata subjects. A separately [frozen first-series header pilot](UPENN_GBM_THIN_T2_HEADER_PILOT_RESULT_2026-10-01.md) confirmed a 0.9 mm physical 3D grid but found 192/192 DERIVED/SECONDARY/OTHER headers with no source-image chain. It proves a released thin grid exists in one candidate, not a native acquisition or atlas-label match for all 83.
In the cached NBIA inventory, those 86 subject prefixes have 83 literal T2, non-FLAIR series and **all 83** carry the Processed_CaPTk description; this bounded name screen found no separately listed unprocessed literal T2 among them. Unusual series descriptions or source data outside this collection/API are not ruled out.

**Decision:** the aligned NIfTI/label route is worth a new, explicitly atlas-space protocol if official package access and a bounded file inventory become available. It cannot strengthen the present DICOM claim by relabeling its 1,496 targets. Before any target-pixel inference:

1. Obtain the official NIfTI package under its stated terms and preserve package/file hashes, scan IDs, T2 volumes and corrected-label filenames. Identify exactly one baseline _11 T2 and corresponding corrected mask per subject; keep absent/duplicate cases in the denominator.
2. Inspect headers only to verify identical shape, orientation and affine/voxel-to-world mapping for each T2/label pair; freeze accepted IDs, target planes, masks/ROI rules and model/checkpoint hashes. If there is no reliable exact same-grid pair, stop rather than registering a label after seeing outcomes.
3. Predefine the primary endpoint as patient-level **tumor-region reconstruction error** against withheld NIfTI T2 target pixels, with a matched non-tumor control and the same fixed phase/context comparison. Report global MSE, tumor-region MSE, boundary-region failure examples and all positive/negative subjects. A retrospective O value alone is not clinical detection or safety.
4. Any claim about segmentation performance requires an independently specified, fixed segmentation model or reader protocol, evaluation against these expert-corrected masks, and a fair equal-information baseline. Do not select a model/threshold from the target outcomes. If tumor-region or task results are null/adverse, report the negative finding.

Atlas registration and image resampling may make the slice series unlike independently acquired through-plane planes. Even a positive tumor-region result would establish only a task-relevant effect **in this processed NIfTI release**; original acquisition identity and DICOM clinical consequences remain separate unresolved questions. The current five-page PDF and three-source DICOM manuscript contain no such experiment.
