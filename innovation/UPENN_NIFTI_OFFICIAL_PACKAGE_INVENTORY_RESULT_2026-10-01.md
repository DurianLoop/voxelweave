# UPENN official NIfTI package: file-level eligibility result

The [prewritten inventory and header-pilot rule](UPENN_NIFTI_OFFICIAL_INVENTORY_AND_PILOT_PLAN_2026-10-01.md) used the public package linked on TCIA's [collection page](literature/source_cache/upenn_gbm_collection_page_2026-10-01.html). The public Faspex client was inspected via its archived [landing/configuration/client assets](literature/source_cache/upenn_gbm_public_package_page_2026-10-01/assets.json). Its own `authorize_public_link` flow supplied a short-lived session; the API v5 file browser returned HTTP 200. No authorization code, bearer token, signed URL or complete transfer spec was saved. The read-only [root tree](literature/source_cache/upenn_gbm_public_package_tree_v4_2026-10-01.json), [full structural/segmentation listings](literature/source_cache/upenn_gbm_public_package_tree_v6_2026-10-01.json), [automated-label and two pilot-directory listings](literature/source_cache/upenn_gbm_public_package_tree_v7_2026-10-01.json), and [CSV reconciliation](literature/source_cache/upenn_gbm_public_package_inventory_2026-10-01.json) preserve the package's returned paths, item counts, response hashes and exact joins. One listing timed out before writing; the same official path succeeded on retry. No image file, NIfTI header or patient pixel was downloaded.

| Official evidence | File-level finding | Interpretation |
|---|---:|---|
| Availability CSV and `/images_structural` directory | 671 exact scan IDs in both; set equality | Each catalog scan has a structural directory, but full file presence was checked only for two pilot directories. |
| CSV `Corrected Tumor Segmentation=Available` | 232 baseline `_11` IDs | This is metadata eligibility, not a verified file count. |
| `/images_segm` | 147 scan-matched `.nii.gz` symbolic-link entries, all within those 232 IDs | **85/232 CSV-marked scans have no entry in this directory.** These 147 are candidate corrected-label files; symlink target accessibility and actual mask content remain untested. |
| `/automated_segm` | 611 `_automated_approx_segm.nii.gz` links; all 232 CSV-marked IDs included | Automated approximate masks are a separate category and cannot silently fill the 85 missing corrected-label entries. |
| T2 acquisition thickness metadata among 147 candidate corrected entries | 60 approximately 0.9 mm; 81 at 3 mm; two at 4 mm; one at 1 mm; three at 5 mm | The thin-grid candidate denominator is **at most 60** before file/header verification, not the CSV's 86. |

The lexicographically first thin-grid corrected-label candidate was fixed as `UPENN-GBM-00002_11`. Its structural directory lists one exact-ID T2 NIfTI link (declared 1,775,300 bytes), and `/images_segm` lists one exact-ID segmentation link (51,227 bytes). The [two-file partial-transfer probe](literature/source_cache/upenn_gbm_partial_transfer_probe_v3_2026-10-01.json) returned HTTP 201 for the official file-level transfer-spec request, without starting a transfer. The authorized public configuration returned `http_gateway_url=null`; no Aspera Connect or `ascp` executable was found locally. Under the frozen stop rule, no unsupported HTTP transfer or 69 GB bulk download was attempted, so **shape, affine, exact same-grid pairing and mask labels remain unverified**.

This corrects the previous assumption that 232 CSV-marked scans might all be usable: the current public package listing directly supports only 147 candidate corrected entries, with 60 thin-T2 metadata candidates. It does not imply the other 85 labels do not exist anywhere or that the 147 symbolic links resolve. The atlas NIfTI/label study remains separate from the frozen 374-patient processed-DICOM result because the official submitter states the two releases do not align by design. The next executable gate is an official Aspera Connect file-level transfer of the two preselected links, then header-only shape/affine comparison. Only after that can a new task protocol be frozen; no clinical or acquisition-identity claim follows from this inventory.
